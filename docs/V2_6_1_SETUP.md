# v2.6.1 上線步驟（照順序做）

v2.6.1 = **名單管理（SPEC F6.1）**：

- 「管理專區」所有人都看得到：還不是球隊管理員的人進去只有「成為球隊管理員」（輸入管理員碼）；升級後看到管理工具，最下面一行小字說明怎麼讓別人也變成球隊管理員。
- 管理專區新分頁「球員名單」：球隊管理員可以**新增球員**（不用等對方加入、認領），也可以**改任何球員的姓名、背號、隊長／副隊長**。
- 同隊背號不能重複、隊長和副隊長各只能有一位（瀏覽器先擋、資料庫再擋一次）；隊長／副隊長可以同時是球隊管理員。
- 順便帶上 v2.6 打完標籤之後才修的一行：Discord 設定成功的提示文字（原本誤寫成「置頂主貼文」）。

**不包含**：練習行事曆、AI 匯入練習（排到 v2.7，見 `docs/SPEC.md` F11）。原本 v2.7 的賽季進步追蹤往後挪到 v2.8，意見回饋／全隊上線關卡挪到 v2.9。

## 1. 資料庫

- [ ] Supabase → SQL Editor 執行 `supabase/migrations/0010_roster.sql`
- [ ] 執行 `supabase/tests/rls_test.sql`，最後出現 `RLS OK`（沙盒已經在本機 PostgreSQL 16 上跑過 0001–0010 + rls_test，通過）

`0010` 新增了：

| 東西 | 做什麼 |
|---|---|
| `add_player(team, name, jersey, badge)` | 球隊管理員新增名單上的球員；名單最多 80 人 |
| `edit_player(player, name, jersey, badge)` | 球隊管理員改姓名、背號、隊長／副隊長；已經連到帳號的球員也能改 |
| `roster_problem(...)` | 兩個函式共用的檢查（姓名 1–40 字不重複、背號 0–999 不重複、C／VC 各一位）；只在有改到的欄位檢查，舊資料本來就重複的不會卡住；登入的人不能直接呼叫 |
| `clean_jersey(text)` | 背號整理：空白 = 還沒決定，`07` 存成 `7`；登入的人不能直接呼叫 |

只新增函式，沒有改資料表、不會動到現有資料。兌換管理員碼用的是 v2.1 就有的 `redeem_coach_code`，這版只是終於做了畫面。
