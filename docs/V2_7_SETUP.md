# v2.7 上線步驟（照順序做）

v2.7 = **練習行事曆與出席（SPEC F11）＋ AI 匯入練習**：

- 「練習」頁改成**月曆**：電腦版滑鼠移到日期上看摘要小卡、點日期在旁邊展開完整內容；手機版格子顯示小圓點、點日期看完整內容。本隊比賽也在月曆上（橘色，點了連到比賽頁）。
- 球隊管理員（和網站管理員）：新增／編輯／刪除一次練習、建立**固定練習**（每週幾、到哪天；建立時就展開成一次一次）、刪除「這一次和之後的整個系列」。
- 出席登記：跟比賽一樣的規則（出席／請假、開始後球員不能改、球隊管理員隨時能代登記或更正）；首頁「我的待辦」提醒下一次練習還沒回覆。
- **AI 匯入**：網站不串接 AI。管理員填基本資訊 → 網站產生「給 AI 的指令」→ 貼給自己的 AI（連同課表／賽程）→ AI 照格式回答 → 貼回網站 → 預覽（錯的那行標出原因、可以直接改文字、可以取消勾選）→ 確認才建立。
- 新增／修改練習、建立固定練習、AI 匯入時，可以各自勾「同時發到站內聊天室」「同時推到 Discord（這隊設定過 Webhook 才會出現）」，預設都不勾。
- 隱私權政策**只改文字**（補上「練習和出席回覆」），**沒有更新 `POLICY_VERSION`**，大家不用重新同意（2026-10-12 使用者決定）。

**不包含**：出席率統計（留到 v2.8 跟賽季進步追蹤一起）、LINE 機器人（之後，v2.9 之後再看）。

## 0. 順序很重要：先跑資料庫，再開網站

這一版的網站一開始就會讀 `practices`、`practice_attendance` 兩張表。**沒執行 `0011` 就打開 v2.7 的網站（localhost 或正式網站），整個球隊頁會讀取失敗。** 所以一定先做第 1 步。

## 1. 資料庫

- [ ] Supabase → SQL Editor 執行 `supabase/migrations/0011_practices.sql`
- [ ] 執行 `supabase/tests/rls_test.sql`，最後出現 `RLS OK`（沙盒已經在本機 PostgreSQL 16 上跑過 0001–0011 + rls_test，通過）

`0011` 新增了：

| 東西 | 做什麼 |
|---|---|
| `practices` 表 | 一次練習：開始、結束、集合時間、地點、標題、內容、備註、`series_id`（固定練習共用） |
| `practice_attendance` 表 | 球員對一次練習的回覆（出席／請假＋40 字備註） |
| `save_practice` | 新增或修改一次；可以順便發聊天室／推 Discord |
| `save_practices` | 一次建立一批（固定練習、AI 匯入）：整批先檢查，有一筆不對就**整批都不建立**並回報是第幾筆；一次最多 60 筆 |
| `delete_practice` | 刪這一次，或「這一次和系列之後的」；已經練過的和它們的出席紀錄留著 |
| `set_practice_attendance` | 練習出席登記 |
| `attendance_who`（小工具） | **比賽和練習共用的出席規則**；`set_attendance`（0008）改成呼叫它，行為不變 |
| `practice_problem`、`practice_announce`（小工具） | 內容檢查、通知；登入的人不能直接呼叫 |
| `notify_discord`（更新） | 多一個只在同一個交易有效的開關，只勾聊天室時這次不推 Discord；一般聊天貼文照舊 |
| `export_my_data`、`delete_my_account`（更新） | 下載資料多了練習出席；刪帳號會刪掉練習出席 |

沒有改現有資料表、不會動到現有資料。
