# v2.5 上線步驟（照順序做）

v2.5 = **比賽列表與出賽登記（F7）** + F4 的一部分：
建立比賽（手動或從系際聯賽賽程一鍵帶入）、出席／請假登記、開賽後鎖定（球隊管理員可更正）、
組隊頁可以把陣容綁定到某一場比賽（出席名單自動跟著那場的登記走）。

**不包含**：比賽狀態只有「即將進行／已結束」，沒有「已分析」；沒有跑動數據、沒有表現評分、
沒有逐場進球／助攻／上場時間記錄——這些是 v3/v4 影片分析的事。

## 1. 資料庫（已完成 2026-10-08，RLS OK）

- [x] Supabase → SQL Editor 執行 `supabase/migrations/0008_matches.sql`
- [x] 執行 `supabase/tests/rls_test.sql`，最後出現 `RLS OK`

`0008` 新增了：

| 東西 | 做什麼 |
|---|---|
| `matches` 表 | 球隊自己的比賽：對手、開賽／集合時間、地點、球衣顏色、賽制、備註、比分。狀態（即將進行／已結束）不存在資料庫裡，用開賽時間和比分算出來 |
| `attendance` 表 | 每場比賽、每個球員的出席登記：`in`（出席）／`out`（請假），沒登記過就是「還沒回覆」（沒有第三種「不確定」狀態） |
| `lineups.match_id`（新欄位） | 陣容可以綁定到某一場比賽；綁定後出席名單改成跟著那場的登記走，不用再手動勾選 |
| `save_match` / `delete_match` | 建立、修改、刪除比賽；只有球隊管理員能用。刪除比賽會一起刪掉出席紀錄，但綁定的陣容不會被刪，只是 `match_id` 清空 |
| `match_from_fixture` | 從系際聯賽賽程「一鍵帶入」：球隊要先在設定填好聯賽隊名；同一場再按一次不會重複建立（回傳 `existed: true`） |
| `set_attendance` | 登記出席／請假／清掉登記；自己登記自己，球隊管理員可以代任何人登記；開賽後一般球員不能再改，球隊管理員仍可以更正 |
| `save_lineup`（改了參數） | 新增 `match` 參數，可以把陣容綁定到比賽；綁定時球員必須是那場登記「出席」的人，賽制也要跟那場比賽一致 |
| `get_shared_lineup`（改了回傳） | 分享頁多回傳比賽的對手和開賽時間（陣容綁定比賽時），不會多回傳其他比賽資訊 |
| `export_my_data` / `delete_my_account`（更新） | 下載資料多了自己的出席紀錄；刪帳號不影響比賽本身 |

只新增東西，不會動到現有的球員、能力表、組隊資料。

## 2. 本機測試

在 VS Code 終端機（PowerShell 擋 `npm` 的話，改打 `npm.cmd`）：

```
git fetch origin
git switch v2.5
py -m pytest
cd web
npm.cmd run typecheck
npm.cmd test
npm.cmd run dev
```

用 Chrome 打開 http://localhost:3000，登入一般球員帳號、再登入球隊管理員帳號各測一次。

### 桌機 —— 比賽頁

- [ ] 球隊管理員：手動新增一場比賽（對手、開賽時間必填；集合時間、地點、球衣、備註選填）
- [ ] 球隊管理員：聯賽賽程表裡還沒建立成比賽的場次會出現在「從系際聯賽賽程帶入」，按「建立比賽」後列表多一場、賽程那場不會再出現在可帶入清單
- [ ] 同一場再按一次帶入（如果還看得到）不會變成兩場重複的比賽
- [ ] 球隊管理員：編輯比賽（改時間、填比分）、刪除比賽（要先按「刪除」再按「確定刪除？」）
- [ ] 一般球員：看不到「＋新增比賽」和「從系際聯賽賽程帶入」
- [ ] 即將進行／已結束兩個分類數字對、列表內容對；填了比分或過了開賽時間的比賽會自動跑到「已結束」
- [ ] 自己登記出席／請假，列表和詳情頁的「出席◯·請假◯·還沒回覆◯」數字會跟著變
- [ ] 再點一次已選的按鈕會清掉登記（變回還沒回覆）
- [ ] 開賽時間過了之後，自己不能再改登記，畫面顯示「比賽已經開始，不能再改…」
- [ ] 球隊管理員在詳情頁「全隊登記狀況」可以幫任何人改登記，包括已經開賽的比賽
- [ ] 詳情頁「去排陣容」連到組隊頁並自動帶入這場比賽

### 桌機 —— 組隊頁接出席名單

- [ ] 組隊頁上方「這組陣容要排哪一場」選一場比賽後，下面的名單變成那場的出席登記（出席才能排進陣容），賽制自動跟著那場比賽
- [ ] 選「不綁定」後名單變回手動勾選，之前勾的狀態還在
- [ ] 綁定比賽時賽制按鈕被鎖住（跟著比賽，不能單獨改）
- [ ] 從比賽詳情頁按「排這場的陣容」進組隊頁，自動選好那場比賽
- [ ] 存檔後重新整理，再打開同一組陣容，綁定的比賽還在
- [ ] 分享這個陣容的連結，分享頁標題下面會多顯示「vs 對手・開賽時間」
- [ ] 「開新陣容」按鈕：如果目前已經綁定了某場比賽，開新陣容後應該維持同一場（不會跳回「不綁定」或報錯）

### 桌機 —— 首頁

- [ ] 有自己隊的比賽時，首頁「下一場」顯示自己隊的下一場（黃框、倒數、出席按鈕），不是系際聯賽賽程
- [ ] 沒有自己隊的比賽、但聯賽賽程有下一場時，退回顯示聯賽賽程版本（標題「下一場（聯賽賽程）」）
- [ ] 兩者都沒有時顯示空狀態，球隊管理員看到的空狀態多一行「去『比賽』頁新增一場」的連結
- [ ] 還沒回覆下一場的人，「我的待辦」會出現「下一場還沒回覆」

### 手機（360 / 390 寬）

F12 → Ctrl+Shift+M → 選寬度 360 和 390 的手機 → F5，兩個寬度都要看過。

- [ ] 比賽列表、詳情頁沒有左右捲動
- [ ] 出席／請假按鈕（`btn-lg`）夠大、好點，兩顆並排不會擠在一起或換行變醜
- [ ] 建立／編輯比賽的表單（兩欄並排的欄位，例如開賽時間／集合時間）在小螢幕上排版正常
- [ ] 組隊頁新加的「排哪一場」下拉不會把原本的賽制／陣型選項擠出畫面
- [ ] 首頁「下一場」卡片（倒數數字 64px）在小螢幕上不會被切掉或重疊
- [ ] 最好用真的手機再看一次（手機連不到 localhost，要等合併上線後用正式網址看）

### 有真實資料後再看

- [ ] 全隊對一場真的比賽登記出席／請假，人數和名單是否符合預期
- [ ] 球隊管理員用真實情境代登記（例如球員傳訊息說要請假，管理員幫忙改）

## 3. 合併到 main（正式上線）

確定手機版沒問題後：

```
git switch main
git pull
git merge v2.5
py -m pytest
git push
```

push 到 main 後 Vercel 會自動重新部署。上線後：

- 打開 https://football-analysis-potato.vercel.app，側邊欄「比賽」可以正常打開（不會再是「即將推出」）。
- 跟球隊管理員說明：之後比賽不用再手動對聯賽賽程算日期，建一場比賽、大家登記出席，排陣容時直接選那一場就好。
